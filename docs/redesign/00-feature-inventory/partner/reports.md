# Partner — Reports

Route(s): `app/(partner)/partner/reports`
Key files: `components/dashboard/kpi-card.tsx`, `components/dashboard/search-input.tsx`, `lib/analytics/date-range.ts`, `lib/analytics/queries.ts` (`getKpis`, `getRevenueOverTime`, `getProductVariantReport` — scoped by `partnerId`), `lib/catalog.ts` (`piastresToEgp`), `lib/format-en-numbers.ts`
API: `GET /api/partner/analytics` (`section=kpis|revenue|products|all`), `GET /api/partner/analytics/export` (`report=summary|revenue|products`)

## Business requirements
- **Goal/KPI**: gives a partner (AGENT-type only — see permission note below) visibility into their own delivered revenue and best/worst-selling variants, so they can plan restocking and judge whether the routing they're receiving is worth their margin. This is an ops-efficiency and partner-retention screen, not a customer-facing one.
- **Trust/credibility signal**: the "تم التسليم فقط" (delivered-only) badge is itself a trust signal to the partner — it tells them these numbers reflect actual completed, paid-out business, not pending/cancelled orders that could otherwise inflate expectations.
- **Friction point**: a partner cannot see revenue from orders still in transit or awaiting delivery confirmation — if delivery confirmation lags, a partner's most recent sales activity is invisible here, which could read as "sales dropped" when they haven't.
- **Compliance/financial**: since this doubles as an informal settlement/reconciliation view (revenue the partner can expect to be paid against), the CSV exports need to remain byte-accurate — this is effectively a financial statement a partner may use for their own bookkeeping.
- **Modern-look rationale**: charts here are currently a plain CSS bar chart (divs sized by inline `height`), not a charting library — any redesign can safely modernize this visually as long as the exact same three CSV exports and the exact same three data sections (KPIs / revenue-over-time / per-variant) survive.

## Elements & behavior
- [ ] **Page-level permission gate** — `requireAgent()` in every backing route calls `requirePartner()` then loads `Partner.partnerType`; if `partnerType !== "AGENT"` (i.e. a DISTRIBUTOR-type partner), every API call returns 403 and the page silently shows no data (no explicit "you don't have access" UI is rendered client-side — the `fetch` failure path just sets `data = null` and renders the empty/zero states). **This is a UX gap to flag, not a security gap**: a distributor-role partner visiting this URL sees a page full of dashes and "no data" messages with no explanation of why.
- [ ] **Header** — title "التقارير" + a static "تم التسليم فقط" success badge (always shown, not conditional) + a one-line description + (once `kpis` loaded) the resolved period as `formatDateEn(from) - formatDateEn(to)`.
- [ ] **Report-period card** — three inputs: `from` date, `to` date (native `<input type=date>`), and a `granularity` select (يومي/أسبوعي/شهري = day/week/month, default day). Below them, 4 preset buttons: "آخر 7 أيام" (7d), "آخر 30 يوم" (30d, also the default range on load), "هذا الشهر" (from = first of current month), "من البداية" (from = `1970-01-01`) — the active preset button is visually highlighted (`variant="default"`) when the current from/to exactly matches that preset's computed range, otherwise all show as outline.
- [ ] **Date clamping rules** (from `lib/analytics/date-range.ts`, shared with admin reports — verify admin equivalents match):
  - `from` cannot be set to a future date (clamped to today).
  - `to` cannot be set to a future date (clamped to today) and cannot be before `from` (clamped up to `from`).
  - Changing `from` shifts `to` by the same span-length the range previously had (e.g. a 7-day window sliding forward), then re-clamps.
  - Empty `from` input resets to 30 days ago; empty `to` input resets to today.
- [ ] **3 KPI cards**: "إجمالي الإيراد" (total revenue, EGP, hint "شامل الشحن ورسوم COD" — includes shipping & COD fees) with an inline "تصدير الملخص" (export summary) link button under it; "صافي المنتجات" (net merchandise, hint "بعد الخصومات، بدون الشحن ورسوم COD" — after discounts, excluding shipping/COD); "طلبات مُسلَّمة" (delivered order count). All three show `loading` skeleton state via the `KpiCard` component's own `loading` prop while `loading && data` (i.e., refetching after the initial load, not the very first paint).
- [ ] **Revenue-over-time card** — "تصدير CSV" export button in the header (independent of the summary/products exports); body renders a simple bar chart (bar height = `round((row/maxRevenue)*120)` px, minimum 8px) with period labels truncated to 3.5rem, followed by a full data table (Period / Total Revenue / Net Merchandise / Orders badge) for every bucket the chart shows — the chart and table are two views of the exact same `revenue` array, always in sync.
- [ ] **Products & variants card** — header shows live counts ("N متغير · M بمبيعات في الفترة" = N variants total, M with sales in the period), a debounce-free client-side `SearchInput` (filters by product name, variant name, SKU, or color name — case-insensitive `includes`, not server-side), and its own "تصدير CSV" export. Table columns: المنتج / المقاس (variant name) / اللون / SKU (monospace) / السعر / مباع (qty sold — shown as a success badge only if >0, else plain "0") / إيراد البنود (line revenue — shown as "- " if zero) / متبقي (stock available — destructive-styled badge if 0) / محجوز (stock reserved, plain text). Rows with `quantitySold > 0` get a subtle green background tint. Table body is `max-h-[32rem] overflow-auto` with a sticky header.
- [ ] **Export buttons** (3, independent of each other) — each opens `/api/partner/analytics/export?report=...&from=...&to=...` (revenue export also passes `granularity`) in a new tab via `window.open`; server streams a UTF-8 CSV with a BOM prefix and a `Content-Disposition: attachment` filename stamped `partner-analytics-{summary|revenue|products}-{YYYY-MM-DD}.csv`. CSV values containing `,`/`"`/newline are quote-escaped. All monetary CSV values are converted from piastres to EGP as a 2-decimal string (`(piastres/100).toFixed(2)`) — **this is a different rounding/format path than the UI's `formatNumberEn(piastresToEgp(...))`**, worth keeping bit-for-bit identical in a rebuild since it's an exported financial artifact partners may compare against the on-screen numbers.
- [ ] **Data scope**: every one of the three data queries (`getKpis`, `getRevenueOverTime`, `getProductVariantReport`) is called with `scope = { partnerId: user.partnerId }` and internally restricted to `Order.status === DELIVERED` only (verified in `lib/analytics/queries.ts`). No other order status contributes to any number on this page.

## States
- [x] Empty state — no data in the selected range: revenue card shows a centered icon + "لا توجد بيانات في الفترة المحددة."; products card shows "لا توجد منتجات نشطة." (or "لا توجد نتائج للبحث." if a search term is active and it's the search that produced zero rows — these are two visually identical empty states with different copy, easy to conflate in a rebuild).
- [x] Loading state — **first load**: whole page replaced by a 5-block skeleton (`ReportsSkeleton`: header bar + 3 KPI blocks + revenue block + products block) under the static "التقارير" H1. **Subsequent loads** (date/granularity change): page stays mounted but gets `opacity-70` and individual KPI cards flip their own `loading` prop; the products table shows `opacity-70` on the `<Table>` itself while `fetching` (not `loading`) is true — two separate loading flags (`loading` vs `fetching`) drive slightly different visual treatments, preserve that distinction.
- [ ] Error state — **not implemented as a visible UI state**: a failed `fetch` (`!res.ok`) just sets `data = null` and stops loading, which renders identically to "no data in range" (KPIs show "-", revenue/products show their empty-state copy). There is no toast, no retry button, no distinct error message anywhere on this page — a genuine 403 (wrong partner type) and a genuine "you have zero delivered orders" look pixel-identical to the partner. Flag for the rebuild: this should probably get a real error state.
- [ ] Permission-restricted state — see "page-level permission gate" above: DISTRIBUTOR-type partners get the same blank/empty-looking page as a genuine zero-data AGENT partner, with no explanation. No redirect, no message.

## Edge cases
- [ ] Setting `from` after `to` via manual typing — `to` auto-clamps up to equal `from` rather than rejecting the input or showing a validation error.
- [ ] Selecting "من البداية" (all-time) — `from` becomes `1970-01-01`; if the shop has years of order history, this is an unbounded query with no pagination on `getRevenueOverTime`/`getProductVariantReport` — confirm current query performance/limits before assuming a rebuild can just "keep it as is" at larger data volumes.
- [ ] Rapid date-range changes trigger a new `fetch` per change (no debounce on date/granularity inputs, only the product-search text field has no debounce either — it's fully client-side filtering of already-fetched data, so no network debounce is needed there specifically).
- [ ] `granularity` change re-fetches the whole `all` payload (KPIs + revenue + products) via `section=all`, not just the revenue section — the KPI cards and product table will visibly flicker/reload even though granularity only affects the revenue buckets.
- [ ] Exports use the *currently selected* from/to/granularity at click time, not necessarily what's currently rendered if a fetch is in flight — verify there's no race where an export reflects a stale filter state.
- [ ] A partner with literally zero delivered orders ever sees three "-" KPI cards and two empty-state messages — verify this is distinguishable in copy from "no orders in this specific date range" (currently it is not — same empty copy either way).

## Notes
- This screen is **read-only** except via the KPI export links — there is no way to drill into an individual order or variant from this page (no links out to order detail, no links to the product's PDP or admin product page).
- The "تم التسليم فقط" framing is load-bearing for partner trust: if the redesign changes what counts toward these numbers (e.g. includes "out for delivery" orders), that must be a deliberate, communicated business decision, not an incidental rebuild side-effect.
- Distinct from `admin/analytics` (store-wide) and `partner/routed-orders`/`partner/orders` (operational, non-financial views) — this is the only place a partner sees their own revenue.
