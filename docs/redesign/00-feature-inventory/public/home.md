# Public — Home

Route(s): `app/(public)/page.tsx`
Key files: `app/(public)/home-sections.tsx`, `app/(public)/layout.tsx`, `lib/storefront-data.ts` (`getHomeData`), `components/shared/hero.tsx`, `components/shared/product-card.tsx`, `components/shared/rotating-product-grid.tsx`, `components/shared/collection-carousel-section.tsx`, `components/shared/view-all-button.tsx`, `components/shared/section-title.tsx`, `components/shared/skeleton.tsx`, `components/shared/header.tsx`, `components/shared/footer.tsx`, `components/shared/menu-drawer.tsx`, `components/storefront/governorate-selector.tsx` (layout-level, every public page), `components/cart/cart-drawer.tsx` (layout-level), `components/promotions/coupon-promo-dialog.tsx` (layout-level), `lib/storefront-location.ts`, `lib/catalog.ts` (`buildProductListItem`)

## Business requirements
- **Goal/KPI**: conversion entry point and category funnel — routes shoppers into Men/Women/Kids category pages, surfaces best-sellers and per-collection cross-sell carousels, and carries brand storytelling ("قصة القطن المصري" / Egyptian cotton origin story) to build trust before the shopper ever reaches a PDP. Acquisition/SEO: indexed at `/` with Arabic metadata (`pageMetadata({ title: "الرئيسية", ... path: "" })`, `og:locale: ar_EG`).
- **Trust/credibility signals**: EGP pricing shown on every product card (`Price` component, `ج.م` suffix); "المصري للمصري" / "قطن مصري أصلي" hero copy asserting authentic Egyptian cotton; meta description explicitly promises "توصيل لجميع المحافظات" (delivery to all governorates) — this promise is **not actually guaranteed by the current fulfillment model** (see Edge cases: a governorate with no active `ReroutingRule`/partner shows every product as out of stock), which is a real gap between marketing copy and system behavior worth flagging to PM.
- **Friction points**: the delivery-governorate picker (`GovernorateSelector`, mounted once in the public layout, appears on every page including home) is not part of the home page's own layout/copy — it's a floating bottom-left pill once an address is saved, or a full modal that auto-opens when no address is saved yet. A first-time visitor therefore sees a home page whose product stock numbers are meaningless (all zero, "نفذ") until they engage with a UI element that isn't visually connected to the products it affects.
- **Compliance/legal**: none specific to this screen beyond standard EGP pricing display; footer links to `/terms` and `/privacy`.
- **Modern-look rationale**: full-bleed hero, rotating collection carousels, and a dark "brand story" band are competitive-parity choices (matches larger EG/regional fashion ecommerce sites) rather than pure aesthetics — they exist to build cotton-authenticity trust and provide category cross-sell without a second click.

## Elements & behavior
- [ ] `Hero` — full-bleed background image (`/hero.png`) with a gradient overlay (bottom-up on mobile, right-to-left on desktop), static Arabic headline "قطن مصري أصلي / إحساس يبان من أول لمسة", eyebrow "المصري للمصري", subcopy. No CTA button. Not personalized, not data-driven.
- [ ] Category banner grid — 3 hardcoded tiles (`CATEGORY_BANNERS` constant in `home-sections.tsx`): رجالي → `/categories/men`, حريمي → `/categories/women`, أطفال → `/categories/kids`. Images are Unsplash stock-photo URLs hardcoded in the component, **not** sourced from the `Category` model or any CMS field. Desktop layout: 2-col/2-row grid with Women spanning both rows; mobile: stacked Men→Women→Kids.
- [ ] "الأكثر مبيعًا" (Best Sellers) section — up to 4 `ProductCard`s. Source: `getHomeData()` computes `bestSellers` by taking `recommended` (products behind the most `AddToCartLog` rows in the last aggregation window) first, falling back to `trending` (`ViewLog` view-count ranking) then `newArrivals` (most recent `createdAt`), de-duplicated by product id, capped at 4. This is **not** an actual sales/order-count ranking despite the label — it's view/add-to-cart telemetry.
- [ ] "قصة القطن المصري" band — full-bleed dark (`#1a1a1a`) section, static Arabic paragraph about Egyptian cotton heritage. No dynamic content, no CTA.
- [ ] 3× `CollectionCarouselSection` (كولكشن السيدات / كولكشن الأطفال / كولكشن الرجال) — each title text is itself a link to `/categories/{women|kids|men}`; each wraps a `RotatingProductGrid` fed by `collectionProducts.{women,kids,men}` (up to 16 products per collection, most-recently-created first, `active: true`, `category.slug` exact match). `RotatingProductGrid` shows 4 at a time and auto-advances every 6s with a 400ms fade transition when a collection has more than 4 products (no rotation, no controls, if ≤4). Each section also renders a "عرض الكل" (View All) button below the grid, linking to the same category.
- [ ] "لماذا ملوك النيل" (Why Nile Kings) — 3 static value-prop cards (المتانة / durability, قطن مصري / Egyptian cotton, الراحة / comfort), icon + title + description, no links, no dynamic data.
- [ ] `ProductCard` (used throughout: best-sellers, carousels) — hover overlay shows two circular icon buttons: "نظرة سريعة" (Eye icon, links to PDP) and "متجر سريع" (ShoppingCart icon, opens `QuickShopModal` in-place without navigating). Discount badge (top-right, amber circle, `-{percent}%`) shown when `discountPercent > 0`. Out-of-stock badge ("نفذ", dark pill, bottom of image) shown when `inStock === false`. Color swatches below the image (when the product has >1 color) — hovering a swatch swaps the card's displayed image to that color's image without navigating; clicking navigates to that color's variant slug via `variantSlug`.
- [ ] Data source `getHomeData()` (`lib/storefront-data.ts`) — the visitor-independent catalog query (`getHomeCatalogData`) is cached 300s via `unstable_cache`; the visitor's partner-specific stock overrides (`getPartnerStockOverrides`/`applyPartnerStockOverrides`) are applied fresh on every request, after the cache read, keyed off the storefront-location cookie's resolved partner.
- [ ] Layout-level chrome present on every public page including home (not specific to home but load-bearing for it): `Header` (logo centered, account icon+dropdown left, cart icon+badge left, hamburger menu right — LTR physical layout even though text is RTL), `Footer` (كل المنتجات / الشروط والاحكام / سياسة الخصوصية links + copyright), `GovernorateSelector` (floating location pill/modal), `CartDrawer` (slide-in mini-cart), `CouponPromoDialog` (session-dismissible promo popup sourced from `Coupon.showPromotionPopup`/`promotionPopupMessage`), Meta Pixel script.

## States
- [ ] Empty state — "لا توجد منتجات بعد" (no products yet) with `Package` icon if `bestSellersSlice.length === 0`; each `RotatingProductGrid` independently shows "لا توجد منتجات في هذا الكولكشن" if its collection is empty.
- [ ] Loading state — the home page is server-rendered (`export const dynamic = "force-dynamic"`), so there is no client-visible network loading state; the "skeleton" branch in `HomeSections` (animated `bg-muted` placeholder blocks matching every section's layout) only renders when `data === null`, i.e. it is functionally an **error fallback**, not a real loading indicator (see Edge cases).
- [ ] Error state — no distinct error UI exists. `getHomeData()` wraps everything in try/catch and returns `null` on any failure (DB outage, query error, etc.), which `HomeSections` renders as the skeleton placeholder described above — a real outage is visually indistinguishable from "still loading," and because the page is server-rendered there is no client-side retry; only a full page reload can recover.
- [ ] Permission-restricted state — not applicable; fully public.

## Edge cases
- [ ] No storefront-location cookie set yet (first-time visitor, or cookie cleared) — `getCurrentStorefrontStockContext()` resolves `partnerId: null`; `getPartnerStockOverrides` then forces **every** variant's `stockAvailable` to `0` for every product on the page (best sellers, all 3 collection carousels), so every `ProductCard` renders the "نفذ" (out of stock) badge and swatches/cards look fully sold out, even though real inventory exists. The `GovernorateSelector` modal auto-opens in this case, but nothing on the home page itself explains *why* everything shows sold out until the shopper notices and interacts with that separate floating element.
- [ ] Selected governorate has no active `ReroutingRule` / no active partner covers it — identical zero-stock behavior to the above, permanently, for that visitor's whole session, with no distinct messaging (same generic "نفذ" badges, no "not deliverable to your area" copy anywhere on this screen).
- [ ] `CATEGORY_BANNERS` hrefs point to `/categories/men`, `/categories/women`, `/categories/kids` — if a future catalog reorganization renames/removes those category slugs, these three tiles 404 silently (no existence check at render time; they are hardcoded, not derived from the `Category` table).
- [ ] Fresh/low-traffic database with no `ViewLog`/`AddToCartLog` rows — best-sellers and all "trending/recommended" signals are empty, so the home page silently falls back to newest-created products everywhere trending/recommended would otherwise show.
- [ ] `CouponPromoDialog` — dismissal is `sessionStorage`-scoped (`nk_coupon_promo_dismissed_session`), so it reappears every new browser session even if previously dismissed; if an admin edits/removes a popup coupon message and adds a new one, only the new message's `id` is un-dismissed (per-message dismiss tracking, not a global "seen promos today" flag).

## Notes
- The literal home-page loading skeleton (`HomeSections` when `data === null`) is dead-code-adjacent as a "loading" state — because the page is fully server-rendered, this branch can only ever be hit by a genuine backend failure, never by an in-flight fetch. A rebuild should treat this branch as an **error state**, not reuse it as a real Suspense/loading skeleton, or shoppers during an outage will believe the site is merely slow.
- The `GOVERNORATE_AS_CITY_VALUES`/partner-stock logic that silently zeroes out all stock for unresolved locations is *shared infrastructure* used by every public catalog screen (home, categories, products, cart, checkout), not something specific to home — but home is the first place a new visitor encounters it, with the least context to explain it.
- "Best sellers" and the collection carousels are analytics-driven (view/add-to-cart logs), not "actual highest revenue/units sold" — a PM expecting true sales-ranked merchandising here should be told this is not currently sales data.
- Category banner images/labels are hardcoded constants, not CMS/DB-driven — any rebuild that wants these editable by non-engineers is a scope change, not parity.
